# Architecture

## Two layers and an engine

Three files make up the whole app. No framework, no bundler.

```
web-api.js   defines window.api          (the bridge)
app.js       consumes ONLY window.api   (the UI)
engine.js    renders                    (pure canvas functions)
```

- **`src/renderer/web-api.js`** defines `window.api`: `kind: 'web'`, folder save
  via the File System Access API in Chrome/Edge, zip download everywhere else,
  plus the test helpers `fromFiles` and `fromDirHandle`. It owns the
  never-overwrite naming rule (`candidateName`).
- **`src/renderer/app.js`** talks only through `window.api`. It never reaches
  around the bridge, which is what keeps a future desktop or server backend
  possible without touching UI code.
- **`src/renderer/engine.js`** is pure rendering: `renderLook`, `applyFrame`,
  `composeStrip`, `encode`, `exifDate`. No DOM access beyond the canvases it
  creates. See [The Engine](engine.md).

## The hardcoded FILES list

`build/build-web.js` copies a hardcoded `FILES` list into `web-dist/`:

```js
const FILES = ['index.html', 'styles.css', 'engine.js', 'web-api.js', 'app.js',
               'icon.png', 'manifest.webmanifest'];
```

A new file in `src/renderer/` never ships until it is added there. The build
fails loudly when a listed file is missing; it stays silent about unlisted ones.

## Generated outputs

- **`web-dist/`** is build output, gitignored. Never hand-edit it; rebuild.
- **`src/renderer/icon.png`** is generated by `build/make-icon.js` (committed,
  since the build and the manifest both need it). Regenerate with
  `npm run icon`.

## Build scripts

`build/build-web.js`, `build/serve-web.js` and `build/make-icon.js` are plain
Node with zero runtime dependencies. `serve-web.js` serves `web-dist/` on
`http://localhost:5178` (the `PORT` env var overrides).
